# پروکسیِ تلگرام با کانالِ اسپانسر

این پوشه یک سرویسِ جداست، **نه بخشی از پنلِ Node**. علتش اینه که نمایشِ
«کانال اسپانسر» به کاربرهایی که از پروکسی‌ت استفاده می‌کنن، فقط با
باینری/ایمیجِ رسمیِ خودِ تلگرام کار می‌کنه — چون این قابلیت نیاز به
مسیریابیِ ترافیک از طریق سرورهای میانیِ (Middle-End) خودِ تلگرام داره که
فقط پیاده‌سازیِ رسمی می‌دونه چطور باهاشون هندشیک کنه. رلهٔ داخلیِ پنل
(`src/mtproto.js`) مستقیم به دیتاسنتر وصل می‌شه و طبق مستنداتِ خودِ
تلگرام، این حالت (direct) با تگِ تبلیغاتی سازگار نیست.

## مرحله به مرحله

### ۱. ساختِ سرویسِ جدید روی Railway
در همون پروژه‌ی Railway که پنل توشه:
- **+ New → GitHub Repo** → همین ریپو رو دوباره وصل کن
- توی **Settings** سرویسِ تازه، **Root Directory** رو بذار: `mtproxy`
- Railway خودش `Dockerfile` همین پوشه رو پیدا و بیلد می‌کنه

### ۲. Volume برای پایداریِ secret
از **Settings → Volumes**، یک Volume به مسیرِ `/data` وصل کن. بدونِ این،
هر ریدیپلوی یه secret جدید می‌سازه و لینکِ قبلی از کار می‌افته.

### ۳. متغیرهای محیطی
| متغیر | توضیح |
|---|---|
| `SECRET` | اختیاری. اگه خالی بذاری، خودش می‌سازه (و با Volume، ثابت می‌مونه). |
| `TAG` | تگی که از **@MTProxybot** می‌گیری — پایینِ همین صفحه توضیح داده شده. |
| `WORKERS` | اختیاری، پیش‌فرض ۲؛ برای ترافیکِ بالا بیشترش کن. |

### ۴. باز کردنِ TCP Proxy
از **Settings → Networking**، برای پورتِ داخلیِ `443` یک **TCP Proxy** بساز.
چون MTProto خام TCP هست، نه HTTP، بدونِ این مرحله از بیرون قابل‌دسترس نیست.
آدرس/پورتی که اینجا می‌گیری (چیزی شبیهِ `xyz.proxy.rlwy.net:12345`) همونیه
که باید توی لینکِ نهایی استفاده بشه — نه دامنه‌ی خودِ پنل.

### ۵. گرفتنِ تگِ اسپانسر از @MTProxybot
۱. اول همین سرویس رو یه‌بار **بدونِ** `TAG` دیپلوی کن و لاگ‌ها رو نگاه کن تا `secret` نهایی رو ببینی (یا خودت از قبل توی `SECRET` ستش کرده باشی).
۲. توی تلگرام، به **[@MTProxybot](https://t.me/MTProxybot)** پیام بده و دستورِ `/newproxy` رو بزن.
۳. آدرس (host از مرحله‌ی ۴) و پورت و secret رو بهش بده.
۴. رباتِ تلگرام یه `TAG` برمی‌گردونه (یه رشته‌ی هگزِ ۳۲ کاراکتری).
۵. اون تگ رو توی متغیرِ محیطیِ `TAG` سرویس بذار و ریدیپلوی کن.

⚠️ **`TAG` پایدار نیست** — هر بار سرویس رو از نو دیپلوی کنی، باید دوباره
همین متغیر رو ست کنی (خودِ ایمیجِ رسمی این‌جوری کار می‌کنه، ربطی به پنلِ ما نداره).

### ۶. ساختِ لینک
```
tg://proxy?server=<host از TCP Proxy>&port=<port از TCP Proxy>&secret=<SECRET>
https://t.me/proxy?server=<host>&port=<port>&secret=<SECRET>
```
همین لینک رو می‌تونی توی پنل، به‌عنوانِ یه پروکسیِ «رسمی» ثبت کنی (تیکِ
«این پروکسی روی سرویسِ رسمیِ جداست» رو توی فرمِ افزودنِ پروکسیِ تلگرام بزن)
تا فقط برای نمایش/کپیِ لینک توی داشبورد ذخیره بشه — پنل دیگه سعی نمی‌کنه
خودش براش لیسنر باز کنه، چون این پروکسی رو خودِ سرویسِ جدا اجرا می‌کنه.
